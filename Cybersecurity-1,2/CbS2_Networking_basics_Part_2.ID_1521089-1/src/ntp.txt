Открыв Wireshark и изучив результирующий файл пакетной трассы, ответим на вопросы:

1. Какой протокол четвертого уровня (по OSI) используется для взаимодействия между
ntp-клиентом и ntp-сервером?
Ответ:
 Протокол 4-го уровня: UDP (User Datagram Protocol)

2. Какие source и destination порты при этом используются?
Ответ:
    Source port: 123
    Destination port: 123

Проверим передаваемое в первом NTP-пакете значение Transmit timestamp, запишем его:

Transmit timestamp: Jan  19, 2005 06:00:42.0660800278 UTC

Значение Transmit timestamp являеться неактуальным, что и требовалось по заданию.
так как мы специально задали на R2 заведомо неверное значение текущего времени,
это: 19 Января 2020 года.
После чего мы произвели синхронизацию с NTP сервером на R1 для получения актульного времени.



Пошагово разберём выполнение задания по настройке NTP.


Настраиваем и запускаем два соединённых между собой роутера, аналогично тому,
как мы это делали в предидущих заданиях:
R1 — будет NTP-сервером. (10.10.10.1/24 на интерфейсе 0/0)
R2 — будет NTP-клиентом. (10.10.10.2/24 на интерфейсе 0/0)

Далее, порядок наших действий:

 1. Настройка NTP-сервера (R1)


На R1 (NTP-сервер):
enable
configure terminal
interface FastEthernet0/0
ip address 10.10.10.1 255.255.255.0
no shutdown
exit
end
write memory

enable
clock set 16:11:00 11 Sep 2025 # Устанавливаем текущее время
configure terminal
clock timezone MSK 3 0 # Задаём часовой пояс
ntp master # Включаем NTP-сервер
end
write memory

Выполняем команды:
(что бы убедиться что нам удалось настроить время и
источник установки времени - NTP.)

show clock
show clock detail

show ntp associations

Проверяем статус:

show ntp status

Если видим что статус: synchronized или master,
значит наш NTP-сервер успешно настроен.



 2. Запустим захват трафика в Wireshark, для захвата пакетов
 в момент когда NTP-клиент синхронизируется.



 3. Настройка NTP-клиента (R2)

Устанавливаем НЕправильное время:
enable
configure terminal
interface FastEthernet0/0
ip address 10.10.10.2 255.255.255.0
no shutdown
exit
end
write memory

enable
clock set 6:00:00 19 Jan 2005

Выполняем команды:
(что бы убедиться что нам удалось настроить неправильное время и
источник установки времени - не NTP.)

show clock
show clock detail

Синхронизируем время у NTP-клиента (R2) c NTP-сервером (R1)

configure terminal
ntp server 10.10.10.1  # Указываем адрес NTP-сервера (R1)


Далее, убеждаемся что всё успешно работет:

show clock
show clock detail

show ntp associations

Проверяем статус:

show ntp status
