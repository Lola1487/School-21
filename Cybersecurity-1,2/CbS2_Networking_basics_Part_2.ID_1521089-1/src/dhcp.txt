Ответим на вопросы:

Что означает вывод «DORA IP …» при DHCP-запросе — каким DHCP-пакетам из пакетной трассы
DORA соответствует?
На какой IP-адрес отправляется первый DHCP-пакет?

Ответы:

Процесс получения IP-адреса по DHCP (DORA):

1. DHCP Discover (D) - Первый пакет в процессе:
   - Клиент отправляет широковещательный запрос (на 255.255.255.255)
   - Содержит MAC-адрес клиента
   - Цель: найти доступные DHCP-серверы в сети

2. DHCP Offer (O) - Ответ сервера:
   - DHCP-сервер отвечает предложением IP-адреса
   - Содержит предлагаемый IP, маску подсети, шлюз и другие параметры
   - Также отправляется на широковещательный адрес

3. DHCP Request (R) - Подтверждение клиента:
   - Клиент подтверждает принятие предложенного адреса
   - Может быть отправлен после получения нескольких Offer (клиент выбирает один)
   - По-прежнему широковещательный пакет (информирует все серверы о выборе)

4. DHCP Acknowledgement (A) - Финальное подтверждение:
   - Сервер подтверждает выделение IP-адреса
   - Содержит полные параметры сети
   - Устанавливается срок аренды (lease time)

Важные особенности:
- Все пакеты, кроме последнего, используют широковещательную рассылку
- Процесс занимает 4 этапа (4 пакета) даже в простейшем случае
- В Wireshark мы увидели именно эту последовательность D-O-R-A
- Время аренды (lease) начинает отсчитываться после получения Ack

Пример из Wireshark:
1. DHCP Discover - Src: 0.0.0.0, Dst: 255.255.255.255
2. DHCP Offer - Src: 10.10.30.1, Dst: 255.255.255.255
3. DHCP Request - Src: 0.0.0.0, Dst: 255.255.255.255
4. DHCP Ack - Src: 10.10.30.1, Dst: 255.255.255.255

Первый DHCP-пакет (Discover) всегда отправляется на IP-адрес 255.255.255.255,
так как клиент еще не знает параметров сети.



Подробный пошаговый разбор выполнения нашего задания:

 DHCP, или Dynamic Host Configuration Protocol (протокол динамической настройки узла),
это сетевой протокол, который позволяет устройствам автоматически получать IP-адреса и
другие сетевые настройки при подключении к сети.
 DHCP упрощает настройку сети, избавляя от необходимости вручную конфигурировать каждый
компьютер или устройство.
 В рамках DHCP, существует DHCP-сервер, который хранит и распределяет IP-адреса и другие
сетевые настройки.
 Клиентское устройство, подключаясь к сети, отправляет запрос на DHCP-сервер для
получения необходимых параметров.
 DHCP-сервер предоставляет клиенту IP-адрес, маску подсети, шлюз по умолчанию, информацию
о DNS-серверах и другие параметры.


Сначала выполним настройку DHCP на роутере Cisco 3745 с IOS 12.4.
(Версию важно учитывать, так как она влияет на то, какие команды мы можем использовать)

1. Подготовка проекта

У нас уже есть проект с двумя соединёнными между собой роутерами (R1 и R2).
R1 —  (10.10.10.1/24 на интерфейсе 0/0)
R2 —  (10.10.10.2/24 на интерфейсе 0/0)

Добавим к нему виртуальный ПК (vPC):

Перетащим из панели устройств объект "VPCS" (виртуальный ПК) на рабочую область

Соединиим его с одним из роутеров (выберем R1) с помощью кабеля

Подключим vPC к свободному интерфейсу роутера (например,М FastEthernet0/1)

2. Настройка интерфейса роутера

Откроем консоль роутера R1 и выполним следующие команды:

enable
configure terminal
interface FastEthernet0/1
 ip address 10.10.30.1 255.255.255.0
 no shutdown
 exit

Эти команды:

Переводят в привилегированный режим (enable)

Выполнения входа в режим конфигурации (configure terminal)

Настраивают интерфейс FastEthernet0/1 с IP-адресом 10.10.30.1/24

Активируют интерфейс (no shutdown)

Выходят из режима конфигурации интерфейса (exit)

3. Настройка DHCP-сервера
Теперь настроим DHCP-сервер на роутере:

enable                                  # Переход в привилегированный режим (режим администратора)
configure terminal                      # Вход в режим глобальной конфигурации

# Настройка исключений для DHCP-пула (адреса, которые НЕ будут выдаваться клиентам)
ip dhcp excluded-address 10.10.30.1 10.10.30.49    # Исключаем адреса с .1 по .49 (резервируем их)
ip dhcp excluded-address 10.10.30.100 10.10.30.254 # Исключаем адреса с .100 до конца сети

# Создание и настройка DHCP-пула с именем MY_POOL
ip dhcp pool MY_POOL                    # Создание нового DHCP-пула с именем MY_POOL
 network 10.10.30.0 255.255.255.0       # Указываем сеть и маску для выдачи адресов
 default-router 10.10.30.1              # Указываем шлюз по умолчанию (адрес роутера)
 dns-server 8.8.8.8                     # Указываем DNS-сервер (используем публичный Google DNS)
 lease 1                                # Время аренды адреса (1 день)
 exit                                   # Выход из режима конфигурации DHCP-пула


Примечание:
Наш диапазон будет 10.10.30.50-10.10.30.99 (ровно 50 адресов)
В сетевых технологиях диапазон считается включительно, поэтому:
10.10.30.50 - первый адрес
10.10.30.99 - последний адрес
Всего: 99 - 50 + 1 = 50 адресов

Если бы выдаваемые адреса не ограничившись конкретным диапазоном, в который не входит адрес роутера,
то нам потребовалось бы исключить из пула адрес роутера командой: ip dhcp excluded-address 10.10.30.1


4. Настройка vPC для получения IP по DHCP
Откроем консоль vPC и выполним:

ip dhcp

# Эта команда заставит vPC запросить IP-адрес по DHCP.

5. Проверка работы DHCP
На роутере (R1) выполним следующие команды для проверки:

Просмотр статистики DHCP:

show ip dhcp server statistics

Просмотр выданных адресов:

show ip dhcp binding


Проверка IP-адреса на vPC:

show ip


6. Включив захват трафика в Wireshark

В vPC снова выполним ip dhcp для генерации DHCP-трафика

Выполним ping с vPC на адрес роутера:

ping 10.10.30.1

Остановиив захват трафика, сохраним дамп как dhcp.pcap




Так же можно выполнить дополнительные проверки на R1:

Команды для проверки DHCP

Проверка исключённых адресов:

show running-config | include excluded-address
или
show running-config | section dhcp

Проверка выданных адресов:

show ip dhcp binding

Статистика DHCP сервера:

show ip dhcp server statistics

Проверка конфликтов:

show ip dhcp conflict
