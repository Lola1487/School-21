Ответим на вопрос:
 Какие тип и класс запроса видны в DNS-запросе?

Ответ:

Тип запроса:
type A (host address),

Класс запроса:
class IN (0x0001)



Пояснение к ответу:

1. Type A (Host Address):
   - Это тип DNS-записи, который преобразует имя домена (например, my.site)
   - в IPv4-адрес (в нашем случае 10.0.0.1)
   - Буква "A" означает "Address" (адрес)

2. Class IN (Internet):
   - Указывает, что запрос относится к интернет-системе
   - IN - это стандартный класс для интернет-запросов
   - 0x0001 - это числовое представление этого класса (hex-формат)

3. Это можно увидеть:
   - В Wireshark при фильтрации "dns"
   - В разделе "Domain Name System (query)"
   - В полях "Type" и "Class" конкретного DNS-пакета

  Дополнительная информация:
- Эти параметры стандартны для большинства DNS-запросов в интернете
- В нашем случае они подтверждают, что:
  * Запрос был типа "A" (поиск IP-адреса)
  * Запрос был отправлен в интернет-классе (IN)


Откроем консоль роутера R1, который будет DNS-сервером.

Перейдём в режим конфигурации:

enable
configure terminal

Создадим Loopback-интерфейс и назначим ему IP:

interface loopback 0
ip address 10.0.0.1 255.255.255.255
# 10.0.0.1 — IP-адрес DNS-сервера.
# 255.255.255.255 — маска (это loopback, поэтому можно так).
no shutdown
exit
end
write memory

Проверим, что интерфейс активен:

show ip interface brief

Должна быть строка:

Loopback0          10.0.0.1        YES manual up                    up

2.2. Включение DNS-сервера и добавление записи
Теперь настроим DNS-сервер и добавим запись для my.site.

Включаем DNS-сервер:

enable
configure terminal
ip dns server
# Добавляем запись my.site, которая будет указывать на 10.0.0.1:
ip host my.site 10.0.0.1
exit
end
write memory

Проверяем настройки:

show running-config | include host

Должно быть:
    hostname R1          # Это имя нашего роутера (не связано с DNS)
    ip host my.site 10.0.0.1  # Это нужная запись! DNS работает.

show hosts # покажет запись my.site

Добавьтеf разрешение DNS-запросов:

configure terminal
ip domain lookup  # Включаем DNS-запросы
ip dns server     # Убедимся, что сервер включён
exit

3. Настройка DNS-клиента
Теперь настроим второй роутер так, чтобы он использовал первый как DNS-сервер.

Перейдём на второй роутер (клиент).

Укажем DNS-сервер (10.0.0.1):

enable
configure terminal
ip name-server 10.0.0.1
exit


3.1 Настроим статический маршрут на R2
Поскольку 10.0.0.1 — это Loopback R1, R2 должен знать, как до него добраться.

Так как R1 и R2 соединены напрямую (например, через 10.10.10.0/24)
На R2 добавим маршрут:

enable
configure terminal
ip route 10.0.0.1 255.255.255.255 10.10.10.1
exit

10.0.0.1 — адрес Loopback R1.

10.10.10.1 — IP R1 на интерфейсе, подключённом к R2.

Проверим, что сервер доступен:

ping 10.0.0.1

Включите DNS-запросы и проверьте:

configure terminal
ip domain lookup
exit
clear dns cache  # Очистка кеша DNS

Теперь после всех настроек, выполним проверки работоспособности:

На DNS-клиенте (R2), что бы узнать адрес DNS-сервера, если бы у нас
была более новая версия IOS, можно бы было сделать командой:

show ip dns primary

Но так как у нас уставревшая, скачанная по ссылке указанной в задании,
версия IOS (12.4), эта команда даст пустой вывод на экран.

Поэтому что бы узнать адрес DNS-сервера, используем вместо неё на R2 команду:

show running-config | include name-server


Далее выполняем на R2:

ping my.site

Убеждаемся что в выводе этой команды на R2 есть ответы по ICMP
(ICMP, или Internet Control Message Protocol, это протокол,
используемый для обмена сообщениями об ошибках и диагностической
информацией между сетевыми устройствами.)
