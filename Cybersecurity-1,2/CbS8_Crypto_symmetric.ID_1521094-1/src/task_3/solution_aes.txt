ЗАДАНИЕ 3: AES

Флаг: S21{good_job!1}

Режим работы, использованный для расшифровки: ECB

ПРОСТОЕ ОБЪЯСНЕНИЕ РЕШЕНИЯ

ШАГ 1. Что дано в задании?

Был файл 4es.py, который шифровал неизвестный текст (plaintext) с помощью алгоритма AES в режиме CBC.
В результате получился шифротекст: dd95b1d1373f97307b1943a00bd9a09fc9568802187663ff93cadfedd688b644

ШАГ 2. В чём проблема (уязвимость)?

Ключ шифрования составлялся так: b'Super_Secret_' + os.urandom(3)
Это значит:
- 13 байт (буквы "Super_Secret_") мы знаем точно.
- Только 3 последних байта — случайные.

3 байта = 24 бита. Всего возможных вариантов такого ключа: 2^24 = 16 777 216.
Это не очень много. Современный компьютер может перебрать все эти варианты за несколько минут.

ШАГ 3. Почему для расшифровки понадобился режим ECB?

В режиме CBC каждый блок шифруется с привязкой к предыдущему. Чтобы это "отключить" и проверить
результаты перебора ключей, удобно использовать режим ECB. Он позволяет расшифровывать каждый
блок независимо.

Алгоритм действий:
1. Берём шифротекст, разбиваем его на два блока по 16 байт.
2. Перебираем все возможные значения 3 случайных байт (от 0 до 16 777 215).
3. Для каждого варианта собираем полный ключ: "Super_Secret_" + текущие 3 байта.
4. С помощью AES в режиме ECB расшифровываем второй блок шифротекста.
5. Выполняем операцию XOR между расшифрованным вторым блоком и первым блоком шифротекста.
   Это позволяет "отменить" эффект сцепления блоков в режиме CBC.
6. Проверяем, начинается ли полученная строка с "S21{". Если да — ключ найден.

ШАГ 4. Результат

После перебора примерно 15 миллионов вариантов найден правильный ключ.
Расшифрованный текст (флаг): S21{good_job!1}

ШАГ 5. Вывод

Сам алгоритм AES не был взломан. Уязвимость возникла из-за того, что случайная часть ключа
была слишком маленькой (всего 3 байта). Это позволило перебрать все возможные ключи
методом "грубой силы".
